# kaspidonations

Детальный план разработки веб-сервиса Kaspi Donations с системой продаж

Цель: Создать коммерческий веб-сервис, который вы сможете продавать стримерам, с надежной защитой от несанкционированного доступа и совместного использования аккаунтов.



Этап 1: Фундамент — Система пользователей с ролями и доступом

Результат: Сайт с регистрацией, входом и админ-панелью для управления пользователями.



Шаг 1.1: Подготовка проекта.

Сохраняем текущую структуру: чистая папка, установка Flask, Flask-SQLAlchemy, Flask-Login, Werkzeug.

Шаг 1.2: Проектирование Базы Данных с ролями.

В server.py мы расширим модель User. Добавим два новых поля:

role: Роль пользователя ('user' или 'admin').

status: Статус аккаунта ('active', 'inactive', 'banned').

machine_id: Уникальный идентификатор компьютера, с которого работает "Агент" (добавим на 3-м этапе, но заложим в базу сейчас).

Шаг 1.3: Создание страниц и админ-панели.

Сохраняем login.html, register.html и auth.css.

Создадим новый HTML-шаблон admin_panel.html — это будет простая таблица со списком всех пользователей и возможностью менять их статус.

Шаг 1.4: Реализация логики управления доступом.

Регистрация: Теперь новые пользователи будут автоматически создаваться со статусом 'inactive'. Они не смогут войти в систему сразу после регистрации.

Вход: При попытке входа система будет проверять не только логин и пароль, но и статус аккаунта. Войти смогут только пользователи со статусом 'active'.

Создание администратора: Напишем отдельную небольшую утилиту (скрипт), которую вы запустите один раз, чтобы создать свой аккаунт администратора.

Админ-панель: Создадим защищенный раздел /admin, доступный только пользователям с ролью 'admin'. В этом разделе вы сможете видеть всех зарегистрированных пользователей и менять их статус с 'inactive' на 'active' (после получения оплаты) или 'banned'.

Этап 2: Воссоздание "сердца" — Онлайн-панель управления для клиента

Результат: Функциональная панель управления в личном кабинете, работающая через защищенный API.



Шаг 2.1: Расширение Базы Данных.

Этот шаг остается без изменений. Добавляем модели Donation, Goal, Settings и связываем их с User.

Шаг 2.2: Адаптация HTML и CSS.

Переносим dashboard.html и dashboard.css в личный кабинет, как и планировалось. Добавим в него информацию о текущем статусе аккаунта клиента.

Шаг 2.3: Создание защищенного API.

План остается прежним. API будет проверять, что пользователь авторизован и его аккаунт активен.

Шаг 2.4: Обновление JavaScript.

Переписываем dashboard.js для работы с новым серверным API.

Этап 3: Создание "Агента" с привязкой к компьютеру

Результат: Локальная программа, которую нельзя просто скопировать и запустить на другом ПК.



Шаг 3.1: Написание скрипта agent.py.

Копируем в него логику чтения уведомлений.

Шаг 3.2: Механизм привязки к ПК.

При первом запуске "Агент" будет генерировать уникальный идентификатор компьютера (machine_id) на основе аппаратных данных (например, MAC-адреса).

"Агент" отправит на сервер свой api_key и этот machine_id. Сервер сохранит machine_id в профиле пользователя в базе данных.

Все последующие отправки донатов от "Агента" будут требовать совпадения и api_key, и machine_id. Если кто-то скопирует "Агента" на другой компьютер, сервер отклонит запросы.

Шаг 3.3: Управление привязкой.

В личном кабинете пользователя на сайте добавим кнопку "Отвязать компьютер". Это позволит вашему клиенту самостоятельно сбросить привязку, если он поменяет свой ПК. После этого он сможет запустить "Агента" на новой машине, и тот привяжется к ней.

Этап 4: Финал — Запуск и развертывание на Render.com

Результат: Полноценный, работающий и защищенный коммерческий веб-сервис.



Шаг 4.1: Создание API для "Агента".

Создаем секретный адрес /api/submit_donation. Он будет принимать данные, проверять api_key и machine_id, и только после этого добавлять донат в базу данных.

Шаг 4.2: Настройка WebSocket и виджетов.

Этот шаг остается без изменений. Виджеты будут публичными и доступными по уникальной ссылке для каждого пользователя.

Шаг 4.3 и 4.4: Подготовка и развертывание.

Готовим requirements.txt, Procfile и развертываем проект и базу данных на Render.com.

Этот план превращает вашу программу в готовый к продаже продукт с несколькими уровнями защиты. Мы можем приступать к реализации, как только вы его одобрите.
